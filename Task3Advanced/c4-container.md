# C4 — уровень контейнеров (целевое состояние, горизонт 3 года)

Целевая архитектура «Будущего 2.0» — слабосвязанная событийная платформа доменов с общим
аналитическим слоем (Data Mesh) и порталом самообслуживания. Camel ESB и DWH SQL Server 2008
сохраняются только как «мосты совместимости» на период миграции и выводятся из критического пути к 36-му месяцу.

**Диаграмма:** [`c4-container.drawio`](c4-container.drawio)

## Соответствие контейнеров доменам Task4Advanced

Контейнер — это развёрнутый в сервисы bounded context. Ниже сопоставление имён, чтобы один и тот же
домен не выглядел разным в разных документах (домены описаны в
[`../Task4Advanced/bounded-contexts.md`](../Task4Advanced/bounded-contexts.md)). Не каждый контейнер
является bounded context: Event Platform, Device Telemetry Gateway и Data Platform (lakehouse) —
платформенные контейнеры, их подписки перечислены в матрице подписок
[`../Task4Advanced/event-storming.md`](../Task4Advanced/event-storming.md), а на Context Map их нет.

| Контейнер                 | Bounded context Task4Advanced    | Примечание                                                                      |
| ------------------------- | -------------------------------- | ------------------------------------------------------------------------------- |
| Портал самообслуживания   | Self-service BI                  | Платформенный контекст: каталог, конструктор, доступ                            |
| Каталог данных и схем     | Data Catalog                     | DataHub; контракты событий ведёт Event Platform                                 |
| Data Platform (lakehouse) | — (платформенный контейнер)      | Lakehouse и потоковые витрины; не bounded context — подписки в матрице подписок |
| Event Platform            | — (платформенная инфраструктура) | Шина событий; владеет Schema Registry                                           |
| Device Telemetry Gateway  | — (платформенный адаптер)        | Приём телеметрии и публикация канонического события                             |

| Пациентский поток         | Patient Flow                     | Заменяет PowerBuilder-логику записи                                             |

## Эволюция контейнеров при масштабировании

Таблица показывает, как целевой ландшафт наращивается по этапам и как выводятся легаси-системы —
это ответ на требование «показать, как изменятся ключевые системы при масштабировании».

| Этап                           | Что появляется / меняется                                                                                                                                                                       | Что происходит с легаси                                                             | Масштабирование бизнеса                                                                                          |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| 0–6 мес (пилот)                | Event Platform (Kafka, Schema Registry, DLQ), IDP + Policy Engine, фундамент Data Platform (Object Storage + Iceberg), ACL-адаптеры; пилотные сервисы Patient Flow и Billing на событиях        | DWH остаётся источником истины; Camel — мост совместимости                          | Один-два домена, единые принципы событий и каталога схем                                                         |
| 6–18 мес (масштабирование)     | Data Platform (lakehouse) целиком, Портал самообслуживания v1, потоковые витрины; сервисы Lending, Inventory & Supply, Corporate Finance; интеграция фарма-партнёров и Device Telemetry Gateway | CDC из DWH, поэтапный read-only по доменам; новые хранимые процедуры запрещены      | Новые направления (аптека, партнёры, электроника), near-real-time витрины                                        |
| 18–36 мес (доменная аналитика) | Региональные контуры платформы, доменные data products по всем направлениям, полная событийная модель                                                                                           | DWH — read-only архив, Camel выведен из критического пути, SQL Server 2008 отключён | 2–3 новых региона с локализацией ПДн, расширение круга партнёров, монетизация ИИ, near-real-time по всем доменам |

Шкала этапов единая для всех документов работы: 0–6 мес (пилот), 6–18 мес (масштабирование),
18–36 мес (доменная аналитика) — это этапы 1, 2 и 3 роадмапа
[`../Task5Advanced/roadmap.md`](../Task5Advanced/roadmap.md) §2. Этап 0 роадмапа (0–2 мес,
платформенный фундамент — до месяца 4) идёт параллельно с началом пилота и укладывается в первый
интервал. Ключевые точки привязки: фундамент Data Platform (Object Storage + Iceberg) — этап 0;
полный lakehouse, портал v1, потоковые витрины и интеграция фарма-партнёров с телеметрией
оборудования — этап 2 (6–18 мес); новые регионы (2–3) с локализацией ПДн и расширение круга
партнёров — этап 3 (18–36 мес).

Правило масштабирования: новый домен или регион добавляется как новый набор доменных контейнеров
и собственных сред lakehouse/Event Platform, без изменения существующих доменов и без новой
бизнес-логики в DWH. Дополнительные источники (фарма-партнёры, телеметрия оборудования) входят
через адаптеры и события, а не через новые таблицы DWH.
