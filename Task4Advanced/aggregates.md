# Агрегаты

Для каждого агрегата: границы (что внутри транзакции), инварианты, ключи. Агрегаты меняются только через команды
в своём контексте; связь с другими агрегатами — по идентификатору.

| Агрегат           | Контекст            | Корень агрегата и состав                            | Ключи                                                           | Ключевые инварианты                                                                                                                   |
| ----------------- | ------------------- | --------------------------------------------------- | --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| Patient           | Patient Flow        | Patient, контактные данные                            | `patient_id: uuid` (UUIDv7), внешний `mrn: text`                | Один активный профиль на человека; дубликаты объединяются событием `patient.patient.merged`; согласия в границу агрегата не входят — их ведёт Identity & Access (`ConsentPolicy`); персональные данные не покидают контекст |
| Appointment       | Patient Flow        | Appointment, слот                                   | `appointment_id: uuid`; `patient_id: uuid`, `employee_id: uuid` | Врач не записан на пересекающиеся слоты; завершить можно только состоявшийся приём                                                    |
| StudyOrder        | Diagnostics         | Назначение, тип исследования                        | `study_order_id: uuid`; `patient_id: uuid`                      | Исследование заказывается только для активного пациента; один заказ — одно исследование                                               |
| Study             | Diagnostics         | Исследование, ссылка на объект-хранилище            | `study_id: uuid`; `study_order_id: uuid`                        | Результат неизменяем после подписания; содержимое хранится только внутри клинического контура                                         |
| AiAnalysis        | AI Analysis         | Запрос, версия модели, статус                       | `analysis_id: uuid`; `study_id: uuid`, `model_version: text`    | Один анализ на пару (исследование, версия модели); результат фиксирует версию модели для аудита                                       |
| Account           | Accounts & Payments | Счёт, баланс, лимиты                                | `account_id: uuid`; `customer_id: uuid`                         | Баланс не уходит ниже лимита овердрафта; каждая операция — проводка (двойная запись)                                                  |
| Payment           | Accounts & Payments | Платёж, статус, идемпотентный ключ                  | `payment_id: uuid`; `idempotency_key: uuid`                     | Платёж по одному `idempotency_key` исполняется один раз; сумма > 0; валюта счёта совпадает                                            |
| LoanAgreement     | Lending             | Договор, график ставок                              | `loan_id: uuid`; `customer_id: uuid`                            | Сумма графика равна телу долга + проценты; изменение условий — только новой версией договора                                          |
| LoanApplication   | Lending             | Заявка, параметры, решение                          | `application_id: uuid`; `customer_id: uuid`                     | Решение принимается один раз по конкретной версии заявки; после скоринга параметры не меняются                                        |
| Disbursement      | Lending             | Выдача средств, транш                               | `disbursement_id: uuid`; `loan_id: uuid`, `account_id: uuid`    | Сумма выдачи не превышает одобренную; один транш — одна проводка                                                                      |
| Repayment         | Lending             | Платёж по кредиту, распределение на тело и проценты | `repayment_id: uuid`; `idempotency_key: uuid`, `loan_id: uuid`  | Один платёж по `idempotency_key`; остаток долга не отрицателен; порядок: проценты → тело                                              |
| RepaymentSchedule | Lending             | График платежей, версия, строки графика             | `schedule_id: uuid`; `loan_id: uuid`, `version: int`            | График строится один раз на версию договора; сумма строк = тело долга + проценты; пересчёт — только новой версией                     |
| CollectionCase    | Lending             | Просрочка, стадия взыскания                         | `collection_case_id: uuid`; `loan_id: uuid`                     | Стадия только вперёд; кейс закрывается при полном погашении или списании                                                              |
| ScoringCase       | Credit Scoring      | Кейс скоринга, факторы, решение                     | `scoring_id: uuid`; `application_id: uuid`                      | Решение воспроизводимо: сохраняются входные факторы и версия модели; скоринг запускается по заявке, до создания кредитного договора   |
| Invoice           | Billing             | Счёт, позиции, налоги                               | `invoice_id: uuid`; `patient_id: uuid`, `appointment_id: uuid`  | Сумма = сумма позиций + налоги; оплаченный счёт неизменяем, корректировка — через `billing.invoice.corrected`                         |
| AiUsage           | Billing             | Учёт использования ИИ, версия тарифа                | `usage_id: uuid`; `analysis_id: uuid`                       | Тарификация по версии тарифа; одна запись на анализ; usage попадает в счёт позицией, а не отдельным платежом                      |
| Settlement        | Billing             | Сверка периода между клиниками и банком             | `settlement_id: uuid`; `period: text` (ГГГГ-ММ)                 | Период закрывается один раз; сальдо сходится с суммой проводок                                                                        |
| Shift             | Workforce           | Смена, сотрудник, роль                              | `shift_id: uuid`; `employee_id: uuid`                           | Нет пересечения смен одного сотрудника; квалификация соответствует роли                                                               |
| StockItem         | Inventory & Supply  | Остаток, партии, срок годности                      | `sku: text`; `location_id: uuid`                                | Остаток не отрицателен; списание только из неистёкшей партии                                                                          |
| PurchaseRequest   | Inventory & Supply  | Заявка на закупку, обоснование                      | `request_id: uuid`; `idempotency_key: uuid`, `sku: text`, `period: text` (ГГГГ-ММ), `location_id: uuid` | Одна заявка на нехватку (`sku` + период) благодаря `idempotency_key`; количество > 0                                                  |
| PurchaseOrder     | Inventory & Supply  | Заказ поставщику, ожидаемая поставка                | `order_id: uuid`; `supplier_id: uuid`                           | Заказ не превышает согласованную заявку; поставщик выбран по действующему SLA                                                         |
| GoodsReceipt      | Inventory & Supply  | Приёмка поставки                                    | `receipt_id: uuid`; `order_id: uuid`                            | Принято не больше заказанного с допуском; остаток обновляется в той же транзакции                                                     |
| ReportingPeriod   | Corporate Finance   | Период, состояние закрытия                          | `period_id: uuid`; `period: text` (ГГГГ-ММ)                     | Период закрывается один раз; после `closed` — только новая версия пакета, не правка фактов                                            |
| Consolidation     | Corporate Finance   | Консолидация показателей периода, набор индикаторов | `consolidation_id: uuid`; `period_id: uuid`                     | Консолидация строится только по закрытым расчётам периода; повторный запуск создаёт новую версию, а не правит прежнюю                 |
| ReportPackage     | Corporate Finance   | Пакет отчётности, версия, получатель                | `report_package_id: uuid`; `period_id: uuid`                    | Отправленный пакет неизменяем; повторная отправка — новая версия с причиной                                                           |
| ConsentPolicy     | Identity & Access   | Согласия, роли, ABAC-правила                        | `subject_id: uuid`; `policy_id: uuid`                           | Отзыв согласия действует немедленно и публикуется событием; доступ к данным другого домена — только явный grant                       |
| DataProduct       | Data Catalog        | Описание, контракт, SLA, владелец                   | `data_product_id: uuid`                                         | Нельзя опубликовать без владельца, схемы и SLA; продукт с тегом `medical_record` отклоняется                                          |

## Принципы

- Агрегат маленький: одна транзакция — один агрегат; согласованность между агрегатами — итоговая (eventual).
- В колонке «Корень агрегата и состав» — только объекты **внутри** границы агрегата. Другие агрегаты не хранятся
  внутри: они доступны исключительно по идентификатору, который указан в колонке «Ключи»
  (например, график платежей у кредитного договора — отдельный агрегат `RepaymentSchedule`).
- Врач — это сотрудник клиники, поэтому в приёме он адресуется как `employee_id`: идентификатор сквозной
  между контекстами, а смены и квалификация принадлежат Workforce.
- **Ключ агрегата и поля payload события — одно и то же множество.** Если ключ агрегата нужен подписчику
  (дедупликация, маршрутизация, сверка), он публикуется в контракте. Ключи, которые не публикуются
  осознанно (например, `mrn` у `Patient`), помечены в колонке «Ключи» как непубликуемые.
- Глобальные идентификаторы — UUIDv7: упорядочены по времени и пригодны как ключ партиции.
- Идентификаторы пациента и клиента банка различаются; связывает их только Identity по явному согласию.
